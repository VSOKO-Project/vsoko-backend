# Спека: учебные периоды и импорт из Excel в админке

Статус: черновик · 2026-10-10

## Зачем

1. **Нагрузка не привязана к семестру.** Семестр хранится только у группы (`StudentGroup.Semester`).
   Если преподаватель ведёт одну дисциплину у одной группы осенью и весной, получается одна запись `Workload`,
   и отзывы за оба семестра смешиваются. Рейтинги нельзя разделить по периодам.
2. **Данные загружает разработчик вручную** через CLI (`src/Tools/ImportStudents`, `src/Tools/ImportWorkloads`)
   с доступом к БД. Админы должны загружать xlsx сами.

## Скоуп

Входит:
- сущность `AcademicPeriod`, привязка `Workload` к периоду, миграция существующих данных;
- управление периодами в админке (список, открыть или закрыть сбор отзывов);
- фильтр по периоду у студента (нагрузка) и у админа (рейтинги, отчёт, сводки);
- импорт студентов и нагрузки из xlsx: шаблон, предпросмотр, применение;
- уникальные индексы против дублей.

Не входит:
- удаление и обновление данных через импорт: импорт только добавляет;
- перевод студента между группами;
- судьба `StudentGroup.Semester`: поле остаётся как есть, решаем отдельно;
- журнал импортов.

## 1. Модель данных

### 1.1 `AcademicPeriod`

`src/Domain/Entities/AcademicPeriod.cs`, `src/Domain/Enums/Term.cs`

```csharp
public enum Term { Autumn = 1, Spring = 2 }

public class AcademicPeriod : BaseEntity
{
    public int StartYear { get; set; }          // год начала учебного года: 2026/27 → 2026
    public Term Term { get; set; }
    public bool IsFeedbackOpen { get; set; }
    public List<Workload>? WorkloadRefs { get; init; }
}
```

Правило: учебный год идентифицируется годом начала. Весна 2027 — это `StartYear = 2026, Term = Spring`.

| StartYear | Term | Отображение |
|---|---|---|
| 2026 | Autumn | 2026/27, осенний семестр |
| 2026 | Spring | 2026/27, весенний семестр |
| 2027 | Autumn | 2027/28, осенний семестр |

Название в БД не хранится, его собирает маппер: `$"{StartYear}/{(StartYear + 1) % 100:D2}, {осенний|весенний} семестр"`.
Сортировка: `ORDER BY StartYear, Term`.

### 1.2 Изменения `Workload`

```csharp
public string PeriodId { get; set; } = null!;
public AcademicPeriod? PeriodRef { get; set; }
```

### 1.3 Индексы

У всех сущностей soft delete (`IsDeleted` + глобальный `HasQueryFilter`), поэтому уникальные индексы
**частичные**: `.HasFilter("\"IsDeleted\" = false")`. Иначе удалённая запись заблокирует повторное создание.

| Таблица | Уникальный индекс |
|---|---|
| `AcademicPeriods` | `(StartYear, Term)` |
| `Workloads` | `(TeacherId, DisciplineId, GroupId, PeriodId)` |
| `Feedbacks` | `(StudentId, WorkloadId)`: сейчас проверяется только в коде (`HasFeedbackAsync`) |
| `Disciplines` | `Name` |
| `Teachers` | `(Surname, Name, Patronymic)` |

Только один период может иметь `IsFeedbackOpen = true`. Индекс: `IsFeedbackOpen` unique с фильтром
`"IsFeedbackOpen" = true AND "IsDeleted" = false`.

### 1.4 Миграция

1. Создать `AcademicPeriods` и вставить период `2026 / Autumn`, `IsFeedbackOpen = true`.
2. Добавить `Workloads.PeriodId` (nullable), заполнить id этого периода, сделать NOT NULL и добавить FK.
3. **Перед созданием уникальных индексов проверить дубли на проде** (ниже). Если они есть, разобрать вручную
   до выката.

```sql
SELECT "TeacherId", "DisciplineId", "GroupId", count(*) FROM "Workloads"
WHERE NOT "IsDeleted" GROUP BY 1,2,3 HAVING count(*) > 1;

SELECT "StudentId", "WorkloadId", count(*) FROM "Feedbacks"
WHERE NOT "IsDeleted" GROUP BY 1,2 HAVING count(*) > 1;

SELECT "Name", count(*) FROM "Disciplines" WHERE NOT "IsDeleted" GROUP BY 1 HAVING count(*) > 1;

SELECT "Surname", "Name", "Patronymic", count(*) FROM "Teachers"
WHERE NOT "IsDeleted" GROUP BY 1,2,3 HAVING count(*) > 1;
```

## 2. Периоды: API и поведение

### 2.1 Эндпоинты (`PeriodsController`)

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| `GET` | `/api/periods` | signed in | список периодов, свежие сверху |
| `GET` | `/api/periods/suggested` | Admin | прошлый, текущий и следующий по дате (для выпадашек), с флагом `exists` |
| `PUT` | `/api/periods/{id}/feedback` | Admin | `{ isOpen: bool }`, открыть или закрыть сбор |

Отдельного «создать период» нет: период создаётся при импорте (раздел 3). При открытии сбора у одного периода
он закрывается у остальных в той же транзакции.

`PeriodDto`: `{ id, startYear, term, title, isFeedbackOpen }`.

### 2.2 Текущий период по дате

`PeriodCalculator.Current(DateOnly today)`:

| Месяц | Term | StartYear |
|---|---|---|
| сентябрь–декабрь | Autumn | текущий год |
| январь | Autumn | текущий − 1 |
| февраль–август | Spring | текущий − 1 |

Используется только для подсказки по умолчанию, ни на какие права не влияет.

### 2.3 Студент

- `GET /api/workload` получает `periodId?`. Без него возвращается нагрузка открытого периода.
- `WorkloadDto` получает поле `Period: PeriodDto`.
- `PostFeedback` и `PutFeedback`: если у периода нагрузки `IsFeedbackOpen = false`, возвращать `ValidationException`
  «Сбор отзывов за этот семестр закрыт».
- Мои отзывы: сгруппировать по периоду, прошлые только для чтения.

### 2.4 Админ

`periodId?` (без него — за всё время) получают:
- `GET /api/teachers/rating`, `GET /api/disciplines/rating`;
- `POST /api/report`: в PDF выводится название периода в шапке;
- `GET /api/summaries/teacher/{id}`, `GET /api/summaries/discipline/{id}`.

Опционально `startYear?` даёт фильтр за весь учебный год, оба семестра.

Ключи кэша (`CacheKeys`) для рейтингов и списков должны включать `periodId`, иначе фильтры будут отдавать
закэшированный ответ другого периода.

## 3. Импорт

### 3.1 Формат файла

Один `.xlsx`, два листа. Можно заполнить любой лист или оба. Первая строка содержит заголовки, сопоставление
по названию колонки без учёта регистра и пробелов, порядок колонок не важен.

**Лист «Студенты»**

| Группа | Фамилия | Имя | Отчество | Номер зачётки |
|---|---|---|---|---|
| ИВТ-21 | Иванов | Пётр | Сергеевич | 210001 |

Отчество необязательно.

**Лист «Нагрузка»**

| ФИО преподавателя | Дисциплина | Группа |
|---|---|---|
| Петрова Анна Ивановна | Математический анализ | ИВТ-21 |

Периода в файле нет: его выбирают в форме импорта.

### 3.2 Эндпоинты (`ImportController`, всё `Admin`)

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/import/template` | отдаёт пустой шаблон xlsx с листами, заголовками и примером строки |
| `POST` | `/api/import/preview` | multipart: `file`, `startYear`, `term`. Парсит и валидирует, **ничего не пишет**. Возвращает `ImportReportDto` |
| `POST` | `/api/import/apply` | те же поля. Повторяет разбор и проверку и применяет в одной транзакции. Если есть ошибки, отдаёт 400 и ничего не пишет |

Файл не хранится между запросами: `apply` парсит заново. Это проще и без состояния, а размер файлов маленький.

Лимит: 5 МБ, до 10 000 строк на лист. Принимается только `.xlsx`.

### 3.3 Ответ

```jsonc
// ImportReportDto
{
  "period": { "startYear": 2026, "term": 2, "title": "2026/27, весенний семестр", "willBeCreated": true },
  "summary": {
    "groups":      { "create": 1,  "existing": 4 },
    "students":    { "create": 30, "existing": 120 },
    "teachers":    { "create": 2,  "existing": 15 },
    "disciplines": { "create": 3,  "existing": 20 },
    "workloads":   { "create": 45, "existing": 0 }
  },
  "errors":   [ { "sheet": "Нагрузка", "row": 17, "message": "Группа «ИВТ-12» не найдена ни в базе, ни на листе «Студенты»" } ],
  "warnings": [ { "sheet": "Студенты", "row": 5, "message": "Студент 210001 уже числится в группе ИВТ-22, оставлен там" } ],
  "studentGroupIds": ["..."]     // только в ответе apply, см. 3.6
}
```

### 3.4 Правила валидации

Общие:
- пустые строки пропускаются; у значений обрезаются пробелы, повторные пробелы внутри схлопываются;
- обязательная пустая колонка или отсутствующий заголовок дают ошибку с номером строки;
- одна и та же строка дважды в файле — предупреждение, вторая игнорируется.

«Студенты»:
- `Номер зачётки` должен быть уникальным в файле, иначе ошибка;
- если студент с таким номером уже есть, он пропускается. Если группа другая, выдаётся предупреждение (студента не переводим);
- если группы нет, она создаётся.

«Нагрузка»:
- в `ФИО преподавателя` не меньше трёх слов: фамилия, имя, отчество (как в текущем `ImportWorkloads`).
  Регистр приводится к виду «Иванов Иван Иванович»;
- группа должна существовать в БД **или** быть на листе «Студенты» этого же файла;
- преподаватель и дисциплина создаются, если их нет. Поиск ведётся по нормализованному ФИО и названию;
- если нагрузка (преподаватель, дисциплина, группа, период) уже есть, строка считается существующей и пропускается.

Порядок применения: период → группы → студенты → преподаватели → дисциплины → нагрузка.

### 3.5 Реализация

- `Application/Features/ImportFeatures/`:
  - `PreviewImportQuery`, `ApplyImportCommand` (`ICommand`, проходит через `TransactionBehavior`);
  - `ImportPlanBuilder`: из распарсенных строк и справочников строит план (что создать, что пропустить, ошибки).
    Его используют оба хендлера, поэтому preview и apply не расходятся.
- `Application/Interfaces/`: `IRosterFileReader`, который читает поток и возвращает строки листов с номерами строк.
- `Infrastructure/FileManager/`: реализация на **ClosedXML** (MIT). EPPlus не используем из-за коммерческой лицензии.
- Справочники (группы, студенты, преподаватели, дисциплины, нагрузки периода) загружаются один раз в словари.
  Запросов на каждую строку нет, в отличие от текущих CLI.
- Создание студентов идёт через `UserManager`, как в `ImportStudents`: `MustChangePassword = true`.
- После `apply` сбрасываются теги `CacheKeys.Workload.ListTag`, `Teacher.ListTag`, `Discipline.ListTag`.
- CLI в `src/Tools` переводятся на `ImportPlanBuilder` или удаляются после выката.

### 3.6 Пароли студентов

Схема паролей не меняется, как в `ImportStudents`: логин — номер зачётки, временный пароль `Vsoko{StudentNumber}`,
`MustChangePassword = true`.

Пароль выводится из номера зачётки, поэтому хранить его не нужно, а выгрузку можно строить в любой момент:

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| `GET` | `/api/import/credentials?groupIds=...` | Admin | xlsx «Группа \| ФИО \| Логин \| Временный пароль», по листу на группу |

- В выгрузку попадают только студенты с `MustChangePassword = true`. Если студент уже сменил пароль, временный
  пароль недействителен, и такой студент помечается в отдельной колонке «Пароль сменён» без пароля.
- Без `groupIds` выгружаются все группы.
- Ответ `apply` содержит `createdGroupIds` и `studentGroupIds` (группы с листа «Студенты»), чтобы фронт сразу
  предложил выгрузку именно по ним.

## 4. Фронтенд

Новые страницы в `src/pages/admin/`, пункты в `Sidebar`, маршруты в `App.tsx` внутри `AdminRoute`.

### 4.1 `/import`, `ImportPage.tsx`

1. Кнопка «Скачать шаблон».
2. Выпадающий список периода: варианты из `/api/periods/suggested`, по умолчанию текущий.
   Если периода ещё нет, у варианта пометка «будет создан».
3. Зона загрузки файла (drag-and-drop и выбор файла). После выбора файла автоматически вызывается `preview`.
4. Результат:
   - карточки summary «создать / уже есть» по каждой сущности;
   - таблица ошибок (лист, строка, сообщение) красным, предупреждений — жёлтым;
   - кнопка «Импортировать», неактивна, если есть ошибки.
5. После `apply`: сообщение об успехе и кнопка «Скачать логины и пароли» по группам из файла
   (`/api/import/credentials?groupIds=...`), если в файле был лист «Студенты».
6. Отдельный блок «Логины и пароли»: выбор групп и кнопка выгрузки, чтобы скачать повторно в любой момент.

### 4.2 `/periods`, `PeriodsPage.tsx`

Таблица: период, количество нагрузок, количество отзывов, переключатель «Сбор открыт».
Включение у одного периода выключает остальные: показать это в подтверждении.

### 4.3 Фильтр периода

Общий компонент `PeriodSelect` (варианты «Все периоды» и конкретные периоды) на страницах рейтингов, отчёта и сводок.
Выбор хранится в zustand, чтобы не сбрасывался при переходах.

### 4.4 Студент

- `WorkloadsPage`: заголовок с текущим периодом, показывается только нагрузка открытого периода.
  Если открытого нет — «Сбор отзывов сейчас закрыт».
- `MyFeedbackPage`: блоки по периодам, прошлые без кнопок редактирования.

## 5. Порядок работ

1. **Модель и миграция**: `AcademicPeriod`, `Workload.PeriodId`, индексы. Перед этим прогнать SQL на дубли на проде.
2. **Периоды**: API, `PeriodCalculator`, проверка открытого периода в отзывах, `periodId` в нагрузке студента.
3. **Импорт (бэкенд)**: reader, plan builder, preview/apply, шаблон, выгрузка логинов и паролей.
4. **Фронт**: `ImportPage`, `PeriodsPage`.
5. **Фильтры**: `periodId` в рейтингах, отчёте и сводках, ключи кэша, `PeriodSelect`.
6. Удаление CLI-тулз из `src/Tools`.

Шаги 1–2 можно выкатить отдельно: существующие данные окажутся в периоде «2026/27, осенний», и поведение для
пользователей не изменится.

## 6. Проверка

- Юнит-тесты: `PeriodCalculator` (граничные месяцы: январь, февраль, август, сентябрь), `ImportPlanBuilder`
  (дубли в файле, группа только на листе «Студенты», существующая нагрузка, кривое ФИО).
- Интеграционные: `preview` ничего не пишет; `apply` с ошибкой ничего не пишет; повторный `apply` того же файла
  ничего не создаёт.
- Ручная проверка: одна и та же пара «преподаватель — дисциплина — группа» в двух периодах даёт две нагрузки,
  студент видит только ту, что относится к открытому периоду.

## Открытые вопросы

- Нужен ли импорт только нагрузки без листа студентов? Сейчас разрешён (любой лист можно оставить пустым).
- Что делать с `StudentGroup.Semester`: удалить или вычислять из периода и года поступления группы?
- Нужно ли админу закрывать период без открытия следующего (каникулы)? Сейчас можно: все переключатели выключены.
