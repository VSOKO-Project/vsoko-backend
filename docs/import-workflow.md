# Импорт и обновление данных

Администратор выбирает семестр, режим и файл `.xlsx`, проверяет план и подтверждает
сохранение. Лимиты: 5 МиБ на файл, 10 000 строк на лист. Ошибки блокируют весь импорт;
изменения применяются одной транзакцией.

## Режимы

| `mode` | Поведение |
| --- | --- |
| `AddOnly` (по умолчанию) | Создание новых записей. Изменения существующих записей не применяются и показываются в предупреждениях. Удалений нет. |
| `UpdateExisting` | Создание и обновление. ФИО и группы студентов сопоставляются по номеру зачётки; преподаватели и дисциплины — по ID из выгрузки. Удалений нет. |
| `SynchronizeWorkloads` | Создание и обновление, а также удаление отсутствующей нагрузки в исходном срезе выгрузки. Нужна корректная выгрузка выбранного семестра. |

Студенты, отсутствующие в файле, никогда не удаляются. Номер зачётки — идентификатор
учётной записи: новый номер создаёт нового студента. Обновление ФИО и группы сохраняет
ID студента, пароль, требование сменить пароль и существующие отзывы.

## Формат файла

`Студенты`: `Группа`, `Фамилия`, `Имя`, `Отчество` (необязательно), `Номер зачётки`.
Номера зачёток следует хранить как текст, особенно при наличии ведущих нулей.

`Нагрузка`: `ФИО преподавателя`, `Дисциплина`, `Группа`. В выгрузке добавляются
`ID преподавателя`, `ID дисциплины`. При исправлении названий сохраняйте ID, при
добавлении новых сущностей оставляйте соответствующие ID пустыми. Одинаковый ID во
всех строках должен иметь одинаковое название. Неизвестные ID и переименование в
название другой существующей записи блокируют импорт; объединение выполняется в
справочнике. Переименования действуют во всех семестрах и сохраняют связи и отзывы.
Без ID записи сопоставляются по имени; новые имена явно перечисляются в отчёте.

Шаблон содержит пустые листы данных и отдельную инструкцию с примерами, которая
не импортируется. Неизменённый пустой шаблон не создаёт демонстрационные записи.

Скрытый лист `_vsoko` хранит исходный семестр, выбор преподавателей и контрольное
количество преподавателей. Его нужно сохранять. Потеря/повреждение среза, удаление
преподавателя из справочника или другой выбранный семестр блокируют синхронизацию;
добавление и обновление остаются доступны. Старые выгрузки без контрольного количества
поддерживаются. Выбор преподавателей ограничивает удаления, а не глобальное переименование.

Удаляется только нагрузка без отзывов. Для удаления всего среза можно оставить
лист `Нагрузка` с заголовками и без строк, сохранив служебный лист. Проверка наличия
отзывов повторяется непосредственно при удалении. Итоговый счётчик отражает фактические
удаления; если во время применения появились отзывы, отчёт предупреждает о сохранении нагрузки.

## API и подтверждение

`POST /api/Import/preview`: multipart `file`, `startYear`, `term`, `mode`.
Ответ включает `previewToken`, выбранный `mode`, `scopeDescription`, `canSynchronize`,
счётчики `create/update/existing/delete`, различия `changes` (было/станет), списки новых
преподавателей и дисциплин, ошибки, предупреждения и предлагаемые удаления.

`POST /api/Import/apply`: те же поля и `previewToken` из проверенного отчёта.
Сервер повторно строит план:

- ошибки файла: `400` с `report`, никаких изменений;
- отсутствующий или устаревший токен: `409` с новым `report`, никаких изменений;
- совпавший план: применение и итоговый отчёт с ID групп для выгрузки доступов.

При `409` интерфейс показывает новый отчёт. Для применения требуется ещё одно явное
подтверждение пользователя; автоматического повторного применения нет. Токен связывает
подтверждение с режимом, периодом, конкретными идентификаторами операций и показанными
различиями, а не только с количеством строк. Это проверка актуальности плана при
применении, а не блокировка базы на время просмотра отчёта.

Изменения контракта требуют обновления backend и frontend. Старая версия frontend,
не передающая токен, получит `409`; развёртывайте обе версии согласованно. Миграция
схемы базы для импорта не требуется.

## Проверки

- Unit: режимы, создание/обновление, конфликты ID, пустой и повреждённый срез,
  защита отзывов, содержимое токена и запрет применения устаревшего плана.
- API с PostgreSQL и Redis: настоящие XLSX, выгрузка и повторная загрузка,
  обновление учётной записи без смены пароля, сохранение связей/отзывов,
  фактические удаления, `400/409` без записи.
- Playwright на компьютере и телефоне: выбор режима, различия, подтверждение,
  повторная проверка, ошибка замены файла, новый план после `409`, итоговый отчёт.
